# Project instructions

These instructions apply to this repository.

- Preserve the distinction between current repository state and proposed/future product behavior. The repository is presently a foundation; do not claim a UI, trained model, benchmark, GPU access, deployment, or production readiness without evidence.
- Keep the MVP bounded to historical maintenance exports, human-reviewed component/fault/action extraction, deterministic analytics, evidence-linked reporting, and validated PDF output.
- Thermal anomaly detection and failure prediction are later phases requiring real authorized labels and asset/time-aware evaluation. Do not invent links between images, telemetry, and work orders.
- Preserve record provenance, reviewer attribution, revision history, and typed claim-to-fact bindings in design and implementation.
- Do not add security scanning, telemetry collection, or live-data integrations unless explicitly requested.
- Run the documented repository checks after edits that affect scripts, configuration, or links. Do not claim these checks test application behavior that does not exist.
- Never commit, push, publish, deploy, change repository visibility, or create/modify GitHub issues or pull requests unless the user explicitly authorizes that action in the current task. Permission for one such action does not imply permission for another.
